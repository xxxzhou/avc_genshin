# BetterGI（better-genshin-impact）主体框架

> 本文档是对 `better-genshin-impact` 主仓库的整体架构梳理，作为系列文档的纲领。
> 代码版本对应仓库 `BetterGenshinImpact.csproj` 中 `Version: 0.62.2`。
> 后续将按本文末尾「细分文档规划」逐层展开。

---

## 1. 一句话定位

BetterGI 是一个 **Windows 桌面自动化工具**，通过 **计算机视觉**（截图 → 识别）+ **模拟输入**（键鼠）的方式操作「原神」游戏，实现自动拾取、自动战斗、自动秘境、自动采集/挖矿、一键日常等能力。它不修改游戏文件、不读写游戏内存，**完全依赖屏幕识别与系统级输入模拟**。

- **技术形态**：C# 12 / .NET 8 / WPF 桌面应用，MVVM 架构，仅 x64
- **目标框架**：`net8.0-windows10.0.22621.0`（WPF + WinForms 同时启用）
- **核心思路**：`截图 → 识别游戏状态 → 决策 → 模拟键鼠`，循环往复

│   TaskTriggerDispatcher(实时回路)  ⇄  TaskRunner(独立任务回路)    │
│   TaskContext(会话) · RunnerContext(单次运行) · CancellationContext│
├──────────────────────────────────────────────────────────────────┤

## 4. 核心执行模型（最重要）

理解整个项目，关键是理解**两套并行的执行回路**。这是 BetterGI 的灵魂。

### 4.1 两种任务形态

| | 实时触发器 `ITaskTrigger` | 独立任务 `ISoloTask` |
|---|---|---|
| 接口位置 | `GameTask/ITaskTrigger.cs` | `GameTask/ISoloTask.cs` |
| 触发方式 | 调度器**每帧**调用 `OnCapture(CaptureContent)` | 主动调用 `Start(CancellationToken)` |
| 控制流 | 无（被调度器回调） | 自有（顺序、循环、等待） |
| 并发 | 多个触发器同帧运行（受优先级/独占/UI场景约束） | **互斥**：`TaskSemaphore(1,1)`，同时只能跑一个 |
| 适用 | 短时间持续识别响应（自动拾取、跳对话、传送…） | 有完整流程的长时间任务（自动秘境、伐木…） |
| 典型 | AutoPick、AutoSkip、QuickTeleport、AutoFishing | AutoDomain、AutoBoss、AutoWood、AutoPathing |

### 4.2 实时触发器回路（高频，~50ms/帧）

```
TaskTriggerDispatcher.Tick()                         [GameTask/TaskTriggerDispatcher.cs]
   │
   ├─ 抢帧锁（上一帧未完成则跳过计数）
   ├─ 检查：捕获器存活？游戏进程在？窗口未最小化？前台/后台触发器策略？
   ├─ frame = GameCapture.Capture()                  → GameCaptureFrame { Mat, RECT }
   ├─ 构造 CaptureContent(frame, frameIndex, interval)
   │        └─ 内部把截图归一化为 1080p ImageRegion
   ├─ Bv.DetectChatUi() / Bv.WhichGameUiForTriggers()  → 判定当前 UI 场景
   ├─ 筛选触发器：
   │      若存在 IsExclusive 触发器 → 只跑它
   │      否则 → 跑所有 IsEnabled 且 SupportedGameUiCategory 匹配的触发器（按 Priority 降序）
   └─ 逐个调用 trigger.OnCapture(content)
```

- 调度器由 `HomePageViewModel` 的「启动」按钮触发 `Start(hWnd, captureMode, interval=50)`
- 初始触发器由 `GameTaskManager.LoadInitialTriggers()` 装载
- 触发器属性：`Priority`（高优先）、`IsExclusive`（独占）、`IsBackgroundRunning`（游戏非前台也跑）、`SupportedGameUiCategory`（仅特定 UI 生效）

### 4.3 独立任务回路（互斥、长流程）

```
TaskRunner.RunSoloTaskAsync(ISoloTask)               [GameTask/TaskRunner.cs]
   │
   ├─ 等待 TaskControl.TaskSemaphore (1,1)            ← 全局互斥锁
   ├─ Init():
   │     ├─ TaskTriggerDispatcher.ClearTriggers()     ← 暂存并清空实时触发器
   │     ├─ SystemControl.ActivateWindow(hWnd)        ← 激活游戏窗口
   │     └─ 新建 CancellationContext + RunnerContext.Clear()
   ├─ task.Start(ct)                                  ← 任务自有控制流
   │     内部常用：TaskControl.Sleep()/CaptureToRectArea()、Bv.*、状态机、PathExecutor
   └─ End():
         ├─ LoadInitialTriggers()                     ← 还原实时触发器
         ├─ Simulation.ReleaseAllKey()                ← 释放卡住的按键
         └─ 清遮罩绘制
```

> 设计要点：独立任务运行时**实时触发器被挂起**，避免两套回路争抢输入；任务结束自动恢复。

### 4.4 三大上下文（理解状态的钥匙）

| 上下文 | 基类 | 位置 | 生命周期 | 关键内容 |
|---|---|---|---|---|
| **`TaskContext`** | 懒初始化单例 | `GameTask/TaskContext.cs` | 游戏会话级（绑定窗口后稳定） | `GameHandle`、`PostMessageSimulator`、`SystemInfo`、`DpiScale`、`AllConfig` |
| **`RunnerContext`** | `Singleton<>` | `GameTask/RunnerContext.cs` | 单次任务运行级（每次 `Clear/Reset`） | `IsSuspend`(暂停)、`PartyName`、`CombatScenes`(队伍)、`AutoPickTriggerStopCount`、`taskProgress` |
| **`CancellationContext`** | `Singleton<>` | `Core/Script/CancellationContext.cs` | 单次任务运行级 | `Cts`、`IsManualStop`（区分用户手动停止 vs 异常） |

> **记忆法**：`TaskContext` = 「连上了哪个游戏窗口」，`RunnerContext` = 「这次任务跑到哪了」，`CancellationContext` = 「这次任务要不要停」。

## 5. 数据流：从截图到操作

这是 BetterGI 每时每刻在做的事：

```
                  游戏窗口（原神）
                        │
            ① 截图  IGameCapture.Capture()
                        │   [BitBlt / WindowsGraphicsCapture / DwmSharedSurface / HDR]
                        ▼
              GameCaptureFrame { Mat(BGR), RECT }
                        │
            ② 归一化  CaptureContent → DeriveTo1080P()
                        │   （任意分辨率 → 统一 1080p 坐标系）
                        ▼
              ImageRegion (1080p)  ── 业务代码 / Bv.* / BvPage.Locator
                        │
            ③ 识别  ImageRegion.Find / FindMulti(RecognitionObject)
                        │   分发：模板匹配 / OCR / YOLO / 颜色 / 特征
                        ▼
                 识别结果 Region (坐标 + 文本 + 置信度)
                        │
            ④ 决策  （触发器逻辑 / 任务流程 / 脚本）
                        │
            ⑤ 输入  Simulation
                        │   ┌─ SendInput     前台硬件级（移动真实光标）
                        │   ├─ PostMessage   后台消息级（游戏无需前台 ← 核心）
                        │   └─ mouse_event   绝对坐标
                        ▼
                  键鼠操作 → 游戏窗口
```

**关键设计：1080p 归一化**。所有识别坐标都以 1920×1080 为基准，模板资源也按 `Assets\1920x1080\` 组织；非 1080p 截图在 `CaptureContent` 阶段缩放，使整套识别逻辑与分辨率解耦。

## 6. 关键子系统概览

> 每个子系统此处仅给「定位 + 入口类 + 一句话」，细节见后续细分文档。

### 6.1 截图（`Fischless.GameCapture`）
- 入口：`IGameCapture`（`Start`/`Capture`/`Stop`）、`GameCaptureFactory.Create(CaptureModes)`
- 4 种模式：`BitBlt`(默认/GDI)、`WindowsGraphicsCapture`(WinRT)、`DwmGetDxSharedSurface`(DWM 共享面)、`WindowsGraphicsCaptureHdr`(HDR→SDR)
- 返回 `GameCaptureFrame { Mat Frame, RECT? CaptureRect }`
- Win11 下 BitBlt 受限，`BitBltRegistryHelper` 写注册表绕过

### 6.2 输入（`Fischless.WindowsInput` + `Core/Simulator/`）
- 库本体：`InputSimulator`（聚合 `KeyboardSimulator`/`MouseSimulator`），唯一 Win32 出口 `SendInput`
- 主项目门面 `Simulation`（`Core/Simulator/Simulation.cs`）三套并存：
  - `SendInput` — 前台硬件级
  - `PostMessage(hWnd)` — **后台消息级**（`PostMessageSimulator`，游戏无需在前台，是「遮罩显示又不抢焦点」的关键）
  - `MouseEvent` — `mouse_event` 绝对坐标

### 6.3 遮罩窗口（`View/MaskWindow`）
- 单例 `MaskWindow.Instance()`，覆盖在游戏上的透明 WPF 窗口
- **点击穿透**：`WS_EX_TRANSPARENT | WS_EX_LAYERED`（`MaskWindowExtension.SetClickThrough`），大地图选点时临时关闭穿透
- **位置同步**：`SetWinEventHook` 监听游戏窗口移动/缩放，实时 `RefreshPositionForNormal()`
- **自绘内容**：识别矩形/线/文字、技能 CD、准星、日志框、地图点位选择器

### 6.4 识别系统（`Core/Recognition/`）
- 统一描述符 `RecognitionObject` + `RecognitionTypes` 枚举（`TemplateMatch/OcrMatch/Ocr/ColorMatch/ColorRangeAndOcr/Detect`）
- 分发入口：`ImageRegion.Find()` / `FindMulti()`（`GameTask/Model/Area/ImageRegion.cs`）
- 四大引擎：
  - **模板匹配**：`MatchTemplateHelper`（OpenCV `MatchTemplate` + NMS 去重）
  - **OCR**：`OcrFactory.Paddle` → `PaddleOcrService`（Det+Rec 双 ONNX 模型）
  - **目标检测**：`BgiYoloPredictor`（YoloSharp，支持 DirectML/CUDA/TensorRT/OpenVINO/CPU）
  - **特征匹配**：`Feature2DFactory`（SIFT/SURF，用于地图定位）
- ONNX 会话统一由 `BgiOnnxFactory` 创建（读 `HardwareAccelerationConfig` 选 Provider）
- 资源加载：`RecognitionAssets` 从 `GameTask/<task>/Assets/Recognition.json` 按 (task, name, 分辨率) 缓存

### 6.5 BgiVision — 类页面对象模型
- 仿 Playwright 的游戏 UI 操作 DSL，两处定义：
  - `Core/BgiVision/`：`BvPage`（`Screenshot/Click/Locator/Ocr`）、`BvLocator`（`FindAll/Click/WaitFor/WithRoi/WithTimeout`）、`BvImage`（`"Feature:asset.png"` 模板描述）
  - `GameTask/Common/BgiVision/`：`Bv` 静态 partial 类 —— `BvStatus`（UI 状态检测：`WhichGameUi/IsInMainUi/IsInBigMapUi/...`）、`BvSimpleOperation`（高层点击）、`BvSkill`、`BvOcr` 等
- 调用链：`Bv.Xxx → region.Find(ro) → MatchTemplateHelper / OcrFactory.Paddle`

### 6.6 自动化任务清单（`GameTask/<各任务>`）

**实时触发器**（`ITaskTrigger`）：
| 任务 | 主类 | 优先级 | 功能 |
|---|---|---|---|
| GameLoading | `GameLoadingTrigger` | 999(后台) | 识别加载界面自动进入 |
| AutoPick | `AutoPickTrigger` | 30 | 识别 F 交互文本自动拾取 |
| AutoEat | `AutoEatTrigger` | 25 | 红血自动吃营养袋/复活 |
| QuickTeleport | `QuickTeleportTrigger` | 21 | 地图选点后自动确认传送 |
| AutoSkip | `AutoSkipTrigger` | 20 | 跳对话/选项/派遣 |
| AutoFishing | `AutoFishingTrigger` | 15 | 实时钓鱼 |
| SkillCd | `SkillCdTrigger` | 10 | 技能 CD 显示 |
| MapMask | `MapMaskTrigger` | 1 | 大地图遮罩绘制 |

**独立任务**（`ISoloTask`）：`AutoFightTask`/`AutoFightJsonTask`、`AutoDomainTask`、`AutoBossTask`、`AutoStygianOnslaughtTask`、`AutoLeyLineOutcropTask`、`AutoWoodTask`、`AutoFishingTask`、`AutoGeniusInvokationTask`、`AutoCookTask`、`AutoArtifactSalvageTask`、`AutoMusicGameTask`/`AutoAlbumTask`、`AutoOpenChestTask`、`AutoEatTask`、`UseRedemptionCodeTask`、`ShellTask` 等。

**热键直接调用的工具任务**（非接口，`HotKeyPageViewModel` 触发）：`QuickBuyTask`、`OneKeyClaimRewardTask`、`QuickSereniteaPotTask`、`OneKeyFightTask`、`OneKeyExpeditionTask`。

### 6.7 自动寻路 AutoPathing（`GameTask/AutoPathing/`）
- 无主接口，入口是 `PathExecutor`（`new PathExecutor(ct).Pathing(task)`）
- `PathExecutor`：按传送点分割路径 → `Navigation` 小地图定位移动到每个航点 → `CameraRotateTask` 转视角 → `TrapEscaper` 卡住脱困 → 到点 `ActionFactory` 分发动作
- `Navigation` / `NavigationInstance`：小地图模板匹配取位置、朝向、距离（经 `MapManager`）
- **动作分发**：`ActionFactory.GetAfterHandler(action)` → `IActionHandler`（`fight`/`combat_script`/`mining`/`pick_around`/`nahida_collect`/`hydro_collect`…/`fishing`/`set_time`/`use_gadget`）；前置处理器（`up_down_grab_leaf`/`stop_flying`）
- 数据模型：`PathingTask` → `Waypoint`(列表) → `WaypointForTrack`(运行时)；航点类型 `Path/Target/Teleport/Orientation`；移动模式 `Walk/Run/Dash/Climb/Fly/Jump/Swim`

### 6.8 战斗系统（`GameTask/AutoFight/`）
- 核心：`CombatScenes`（队伍场景，`Avatars[]`，YOLO 侧栏识别）+ `Avatar`（单角色）
- 策略：`AutoFightParam.ResolveStrategyPath` 自动选 `.json`/`.txt` 策略；`User\AutoFight\` 按队伍名匹配
- 执行：`CombatScriptExecutor.ExecuteAsync` → 解析 `CombatScript`/`CombatCommand` → 发招
- 工厂：`CombatTaskFactoryProvider` 按文件扩展名选 `Json/TxtCombatTaskFactory`
- 角色配置：`combat_avatar.json`（别名→标准名映射）

### 6.9 一条龙 OneDragon
- 编排：`OneDragonFlowViewModel.OnOneKeyExecute()`（`ViewModel/Pages/`）
- 任务单元：`OneDragonTaskItem`，`InitAction()` 按 Name 绑定到 ISoloTask（领邮件→`ClaimMailRewardsTask`、合树脂→`GoToCraftingBenchTask.GoCraftResin`、秘境→`AutoDomainTask`、首领→`AutoBossTask`、地脉花→`AutoLeyLineOutcropTask`…）
- **断点续跑**：`OneDragonFlowConfig.NextTaskId` + `IsNextTask` 标记，执行时 `Skip` 到断点
- 复用 `GameTask/Common/Job/` 下 20+ 个通用子任务（`ReturnMainUiTask`、`GoToCraftingBenchTask`、`SwitchPartyTask`…）

### 6.10 脚本系统（`Core/Script/`，ClearScript V8）
- 脚本项目：`ScriptProject` 读 `manifest.json`，`ExecuteAsync` 建 `V8ScriptEngine` 执行 JS
- 配置组：`ScriptGroup` / `ScriptGroupProject`（条目类型 `Javascript/KeyMouse/Pathing/Shell`）
- **宿主注入**：`EngineExtend.InitHost()` 把 C# 对象暴露给 JS：
  - `dispatcher`（任务调度）、`genshin`（游戏操作：传送/队伍/位置…）、`pathingScript`（执行路径 JSON）、`keyMouseScript`（播放宏）
  - `log`/`file`/`http`/`notification`/`htmlMask`/`host`
  - 全局方法：`sleep`/`click`/`keyPress`/`captureGameRegion`/`getAvatars`…
  - 类型：`BvPage`/`BvLocator`/`BvImage`、`RecognitionObject`、`CombatScenes`、`Mat`…

### 6.11 状态机（`GameTask/Common/StateMachine/`）
- `StateMachineBase<TState, TContext>`：通用泛型有限状态机
- 特性注册：`[StateHandler]`/`[StateDetector]`/`[UnknownStateHandler]`，`RegisterStateMethodsByAttribute()` 反射注册
- `StateHandlerResult`：`Success`/`Wait`/`Retry`/`Fail`；邻接图限制检测范围提升性能
- 代表子类：`SwitchCharacterStateMachineTask`、部分钓鱼逻辑

### 6.12 配置系统（`Core/Config/`）
- `AllConfig`（`ObservableObject`）聚合 ~30 个子配置（`MaskWindowConfig`/`CommonConfig`/各 `AutoXxxConfig`/`MacroConfig`/`ScriptConfig`/`HotKeyConfig`/`HardwareAccelerationConfig`…）
- `ConfigService`（`Service/`）读写 `User/config.json`，`ReaderWriterLockSlim` 保护，失败自动备份
- 变更链：任一子配置 `PropertyChanged` → `AllConfig.OnAnyPropertyChanged` → `GameTaskManager.RefreshTriggerConfigs()` + 存盘

### 6.13 MVVM 与 UI
- DI 注册集中在 `App.xaml.cs`（Generic Host）：`services.AddView<Page, ViewModel>()` 成对注册
- `MainWindow`（`FluentWindow` + `INavigationWindow`）+ `MaskWindow`（遮罩）
- 页面：`HomePage`(启动)、`ScriptControlPage`(调度组)、`TaskSettingsPage`、`TriggerSettingsPage`、`MacroSettingsPage`、`CommonSettingsPage`、`HotKeyPage`、`NotificationSettingsPage`、`KeyMouseRecordPage`、`JsListPage`、`MapPathingPage`、`OneDragonFlowPage`、`KeyBindingsSettingsPage`
- 启动路由：`ApplicationHostService` 按命令行参数 `Action` 跳转首页（`StartOneDragon`/`StartGroups`/默认）
- 规范：VM 继承 `ObservableObject`，`[ObservableProperty]`/`[RelayCommand]`；对话框用 `ThemedMessageBox`

### 6.14 多开（`Service/Instance` + `Service/ChildSession`）
- **实例 IPC v2**（命名管道）：三种实例 `Primary`/`ChildSession`/`WebView`，按用户 SID 隔离管道
- `InstanceBootstrap` 启动期判定身份；`InstanceService`(IHostedService) Primary 接受连接 / 子实例连回；`InstanceRequestHandler` 路由消息（激活去重、WebView 隔离、相对鼠标转发）
- **桌面分身**：`ChildSessionService` 基于 Windows RDP Child Session，`ChildSessionProcessLauncher` 以管理员在新 Session 启动 BetterGI
- 相对鼠标：主实例捕获 RawInput 增量 → 批量转发给 ChildSession（`RelativeMouseMessageHandler`）

### 6.15 通知系统（`Service/Notification` + `Service/Notifier`）
- `NotificationService`(IHostedService) + `NotifierManager` 广播
- 入口：`Notify.Event(NotificationEvent).Send()` → 订阅过滤 + 附截图 → 各渠道并行
- `NotificationEvent` 枚举所有事件码（`domain.reward`/`task.error`/`dragon.start`/`js.custom`…）
- **14 种渠道**：Webhook、Windows UWP Toast、飞书、OneBot(QQ)、企业微信、WebSocket、Bark、Email(SMTP)、钉钉、Telegram、Server酱、Discord、xxtui、Meow

### 6.16 地图（`GameTask/Common/Map/` + `Service/`）
- 小地图定位：`MapManager` 按 `"{mapType}_{method}"` 缓存 `ISceneMap`（提瓦特/层岩/渊下宫…，SIFT 或模板匹配）
- 大地图点位 API（三套，`MaskMapPointService` 聚合）：米游社 `MihoyoMapApiService`、HoYoLab `HoYoLabMapApiService`、空荧酒馆 `KongyingTavernApiService`
- 朝向计算：`CameraOrientation`/`CharacterOrientation`
- 坐标系互转：游戏坐标 ↔ 图像坐标 ↔ 网页地图坐标

### 6.17 Wine 兼容（`Wine/`）
- `WinePlatformAddon`：检测 Wine 环境（`wine_get_version`）→ 强制软件渲染（解决 WPF 黑屏）→ `GetAsyncKeyState` 轮询替代不可靠的全局钩子
- `MouseKeyMonitor.Wine.cs`：15ms 轮询 F/Space 键，实现「长按变连发」并经 `PostMessage` 后台注入

## 8. 关键设计约定

1. **1080p 归一化** —— 所有识别以 1920×1080 为基准，资源按 `Assets\1920x1080\` 组织，运行时按 DPI/分辨率缩放。仅支持 16:9。
2. **单例驱动的全局状态** —— `TaskContext`/`RunnerContext`/`CancellationContext`/`TaskTriggerDispatcher` 均为单例，任务代码直接静态访问（`TaskControl` 提供 `using static` 快捷方式）。
3. **两种回路互斥协作** —— 独立任务运行时挂起实时触发器，结束自动恢复；`TaskSemaphore(1,1)` 保证独立任务全局唯一。
4. **描述符驱动的识别** —— 统一用 `RecognitionObject` + JSON(`Recognition.json`) 描述识别目标，代码与资源解耦。
5. **前后台输入双轨** —— `SendInput`（前台/需焦点）与 `PostMessage`（后台/不抢焦点）并存，遮罩显示与真实操作分离。
6. **MVVM + Generic Host DI** —— `AddView<Page,VM>` 成对注册，`IHostedService` 管理生命周期服务。
7. **配置即代码** —— `AllConfig` 聚合所有子配置，`ObservableObject` 变更自动触发刷新与存盘。
