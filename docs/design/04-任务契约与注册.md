# 04 · 任务契约与注册 —— AI 写任务的接口规范

> 本文档钉死 AI 写任务时的**接口**:`@task` 完整字段、`main` 签名/返回/异常约定、`TaskDescriptor`、`TaskRegistry` 行为、任务组合 `ctx.run`、生命周期。
> 是 `00 §3/§5` 的展开;前置:`00`/`01`/`02`/`03`。
> **AI 生成任务脚本时,以本文为格式规范**;一次生成即命中契约,无需试错。

---

## 0. 一句话

任务是 avc_genshin 的一等公民。AI 写一个 `@task` 装饰的 `main` 函数,落到 `src/tasks/`,框架**即接纳、即暴露、即可按名调用、可组合**。这条路径的顺畅度是框架成败的核心指标(`00 §5.3`)。

---

## 1. 任务契约总览

```
AI 生成 src/tasks/collect_flowers.py
   ├─ @task(name=..., desc=..., daemons=..., params=...)   ← 元数据(框架与 AI 都能读懂)
   └─ def main(ctx, g, **params): ...                       ← 入口(统一签名)
        │
        ▼  Registry 发现 + 注册(import + 提取 @task → TaskDescriptor)
   TaskRegistry["collect_flowers"] = TaskDescriptor(...)
        │
        ▼  立即可用
   ctx.run("collect_flowers", count=5)                      ← 按名调用/组合
   Runtime.run_task("collect_flowers", count=5)             ← 直接跑
   planner 枚举 registry.list() 时能复用它                  ← AI 规划时复用
```

**契约三要素**:① 元数据(`@task` 字段)② 入口(`main(ctx,g,**params)`)③ IO 约定(参数 schema + 返回 dict + 标准异常)。

---

## 2. `@task` 完整字段

### 2.1 核心字段(必填/常用)

| 字段 | 类型 | 必填 | 默认 | 语义 |
|---|---|---|---|---|
| `name` | str | ✅ | — | 全局唯一注册名(AI 按名调用/组合;建议 snake_case) |
| `desc` | str | ✅ | — | 一句话描述(**AI 规划时据此判断是否复用此任务**,要写清"做什么、何时用") |
| `daemons` | list[str] | ❌ | `[]` | 运行时自动挂载的守护名(如 `["auto_skip"]`);见 §8 |
| `params` | dict | ❌ | `{}` | 参数 schema;AI 据此传参,框架据此校验;见 §2.3 |
| `requires` | list[str] | ❌ | `[]` | 依赖的领域能力(如 `["navigation","fighter"]`);供规划器校验/提示 |

### 2.2 高级字段(可选)

| 字段 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `preconditions` | list[str] | `[]` | 执行前需满足的状态(如 `["at:mondstadt"]`);规划器校验链可满足性,自动插入桥接任务(传送) |
| `postconditions` | list[str] | `[]` | 执行后保证的状态(如 `["daily_claimed"]`);供组合链校验 |
| `needs_confirm` | bool | `False` | 高风险任务,执行前人类确认(接 `02 §5` Policy) |
| `tags` | list[str] | `[]` | 分类标签(`daily`/`domain`/`collect`/`combat`...);供规划器筛选 |
| `version` | str | `"0.1"` | 任务版本(游戏更新致失效时,AI 据可观测回流感知并重写) |

### 2.3 `params` schema 格式

```python
params = {
    "count": {"type": "int",   "default": 4,    "desc": "委托数量",   "required": True},
    "name":  {"type": "str",   "default": "绝缘","desc": "秘境名"},
    "fast":  {"type": "bool",  "default": False, "desc": "跳过过场动画"},
}
```

- 支持类型:`int`/`float`/`str`/`bool`/`list`/`dict`。
- 框架在调用前**自动校验**:必填项缺失 → `InvalidParams`;类型不符 → 转换或报错。AI 传参无需自己转换。
- `default` 让 AI 可省略非关键参数;`desc` 供 AI 理解每个参数含义。

## 3. `main` 入口签名

```python
def main(ctx, g, **params) -> dict | None:
    """
    ctx = GameContext  (avc 实例:sc/ic/tm/ocr;见 IMPLEMENTATION §4.1)
    g   = HighLevelApi (高层语义 API;见 01 §6)
    params = 经框架校验/注入默认值后的参数(与 @task.params 对应)
    返回:dict(结构化,记入日志 task_return)或 None
    """
```

### 3.1 返回值约定

- 返回 `dict`:`Runtime` 自动记一条 `task_return` 事件(含 `return_value`)到日志;调用方(`ctx.run`)拿到该 dict。
- 返回 `None`:视为成功无返回值。
- **不要**返回不可 JSON 序列化的对象(日志要落 JSONL)。

### 3.2 异常约定(统一异常体系 `framework/errors.py`)

| 异常 | 语义 | Runtime 处理 | 日志 |
|---|---|---|---|
| `NormalEnd(reason)` | **正常**提前结束(非错误,如"今日已领过") | 当成功结束 | `task_return` + `normal_end` 标记 |
| `Retry(times, reason)` | 请求重试本任务 | 默认重试 3 次,仍失败转 `TaskError` | `retry` 事件 |
| `TaskError(reason)` | 任务失败(预期内的错) | 记失败,向上传播 | `failure`(failure_type 取 reason 映射) |
| 其它未捕获异常 | 未预期错误 | 记失败,向上传播 | `failure`(failure_type=`UnexpectedError`)+ 存证截图 |

> 任务作者**主动**用 `NormalEnd`/`Retry`/`TaskError` 表达业务语义;框架捕获一切并保证**卸载守护 + 释放按键**(01 §8.4)。任务无需写 try/finally 清理。

## 4. TaskDescriptor(注册表里的任务描述)

`TaskRegistry` 内部为每个任务存一个 `TaskDescriptor`(供执行器调用、供规划器枚举):

```python
@dataclass
class TaskDescriptor:
    name: str
    desc: str
    daemons: list[str]
    requires: list[str]
    params: dict                 # 参数 schema
    preconditions: list[str]
    postconditions: list[str]
    needs_confirm: bool
    tags: list[str]
    version: str
    # ── 框架内部 ──
    source: Path                 # 来源文件(src/tasks/x.py 或 cache/tasks/<hash>.py)
    module: ModuleType           # 已加载的模块(含 main)
    kind: str                    # "persistent" | "ephemeral"(持久/即时)
    loaded_at: float             # 加载时刻(热加载判断用)
```

`registry.list()` 返回**精简视图**(去掉 `module`/`source` 等),供 AI 规划器枚举:`[{name, desc, params, tags, requires, ...}]`。

## 5. TaskRegistry 行为

```python
class TaskRegistry:
    def discover(self): ...                    # 启动扫描 src/tasks/ + cache/tasks/
    def register(self, module_or_path): ...    # 注册(持久任务正常 import;即时任务经沙箱 exec)
    def get(self, name) -> TaskDescriptor      # 按名取(不存在 → TaskNotFound)
    def list(self, filter=None) -> list[dict]  # 供规划器枚举(可按 tags/requires 筛)
    def reload(self, name): ...                # 热重载单任务(AI 修改后)
    def unregister(self, name): ...            # 卸载
```

### 5.1 发现(两个扫描根)

- **`src/tasks/`**:持久任务(进 git)。启动时 `discover()` 扫描 `src/tasks/**/*.py`,凡含 `@task`(或降级的 `def main(ctx,g)`)自动注册。
- **`cache/tasks/`**:即时任务(AI 现场生成,gitignore)。同样扫描,`kind="ephemeral"`。

### 5.2 注册

- **持久任务**:正常 `importlib.import_module`(已是 `src/` 下的包/模块)。
- **即时任务**:经沙箱 `exec`(01 §5),白名单校验后注册,`kind="ephemeral"`。
- 提取 `@task` 元数据 + `main` 函数 → 建 `TaskDescriptor`。

### 5.3 热加载

- 文件 watcher 监视两个根;变更 → `reload(name)`(重新 import + 替换 Descriptor)→ **无需重启**。
- import 失败(语法错/缺依赖)→ **保留旧版本**,记 `failure`(failure_type=`LoadError`)→ 回流给 AI 修正,**不影响**其它已注册任务。

### 5.4 命名冲突

- 同名注册 → 后者覆盖前者,并 `warn`(记日志)。建议 `name` 全局唯一;冲突时 AI 据日志改名。
- 持久与即时同名 → 持久优先(即时被忽略并 warn)。

## 6. 任务组合 `ctx.run`

一个任务的 `main` 里可直接调用其他任务——纯 Python 函数调用,**非**配置编排:

```python
@task(name="one_dragon", desc="一键日常", tags=["daily"])
def main(ctx, g):
    ctx.run("claim_mail")                           # 无参
    craft = ctx.run("craft_resin", times=3)         # 带参,拿返回值
    ctx.run("daily_quest", count=4)
    ctx.run("farm_domain", name="绝缘", times=3)
    return {"all_done": True, "resin_crafted": craft["amount"]}
```

### 6.1 `ctx.run(name, **params) -> dict | None`

- **串行**:一次调用跑完一个任务(单线程 loop,Runtime 天然串行,01 §8.3)。
- **参数**:按子任务的 `@task.params` schema 校验/注入默认值后传入。
- **返回值**:子任务 `main` 的返回 dict(或 None)。
- **异常传播**(关键):
  - 子任务 `NormalEnd` → `ctx.run` 返回 `None`(正常)。
  - 子任务 `Retry` → `ctx.run` 内部重试(默认 3 次);仍失败 → 转 `TaskError` 向父传播。
  - 子任务 `TaskError` / 未捕获异常 → **向父传播**(父可选择 catch 或放任)。

### 6.2 守护与上下文隔离

- **守护**:子任务的 `@task.daemons` 在 `ctx.run` 进入时自动 mount、退出时 unmount;**父任务已挂的守护保持不变**(不被子卸载)。父子/兄弟守护冲突由 `InputAuthority`(02 §2)仲裁。
- **共享**:GameContext / SharedState(scene/frame)在整个运行**共享**(同一游戏会话)。
- **隔离**:每次 `ctx.run` 建子 `RunContext`(统计/日志的 `task` 字段切换为子任务名);嵌套深度有限制(默认 8,防递归)。

## 7. 任务生命周期 + 即时→持久提升

```
[持久任务]  src/tasks/x.py ──discover──▶ Registry ──ctx.run/run_task──▶ 执行 ──▶ 返回/异常
[即时任务]  intent ──AI生成──▶ cache/tasks/<hash>.py ──discover──▶ Registry ──执行
                                                              │
                              (效果好/复用多次)                ▼
                                         提升:移入 src/tasks/ + 补 @task 元数据 + 提交 ──▶ 持久任务
```

- **执行期**(任何任务):挂 daemons → 跑 main → 卸 daemons + 释放按键 → 记日志(task_return/failure)。
- **提升**:即时任务反复被复用/效果稳定时,AI 或用户将其从 `cache/tasks/` 移入 `src/tasks/`,补全 `@task(name/desc/...)` 元数据并提交 git → 成为持久任务。框架能力**随使用自我积累**(`00 §3.2`)。

---

## 8. 与可靠性地基(02)和工程骨架(03)的衔接

- **`@task.daemons=["auto_skip"]`** → Runtime 执行时自动 `ctx.mount("auto_skip")`;守护的 `owns_keys`/`scenes` 在 **Daemon 定义**里(02 §2),不在 task。任务只声明"我要哪些守护",不管守护的并发安全。
- **`@task.needs_confirm=True`** → 接 `02 §5` Policy:执行前人类确认。
- **`@task.requires=["navigation"]`** → 规划器校验能力可用(起步仅文档/提示;后续可强制)。
- **扫描路径**:`src/tasks/` + `cache/tasks/`(03 §4),由 `TaskRegistry.discover()` 负责。
- **日志**:执行全程自动写 `logs/<run_id>.jsonl`(03 §7),任务作者无需手写。

## 9. 降级形态(无装饰器极简脚本)

框架也接受**最简形态**——只有 `def main(ctx, g):`,无 `@task`:

```python
# cache/tasks/<hash>.py —— AI 现场生成的即时任务
def main(ctx, g):
    g.teleport_to("蒙德城")
    g.go_to((123, 456))
    g.talk("领取奖励")
```

- 元数据从**函数名/模块名/文档串**推断(`name`=文件名,`desc`=docstring 或空)。
- 适合 AI 快速生成一次性脚本;成熟后提升时再补 `@task` 元数据。
- **持久任务建议用完整 `@task`**(desc 对 AI 规划复用至关重要)。

## 10. 端到端示例(AI 写任务的范本)

```python
# src/tasks/daily_quest.py
from framework import task, KeyCode
from framework.errors import NormalEnd, Retry, TaskError

@task(
    name="daily_quest",
    desc="完成每日委托并到凯瑟琳处领取奖励。每天调用一次。",
    daemons=["auto_skip"],                       # 对话自动跳过
    requires=["navigation"],                     # 需要导航能力
    tags=["daily", "commission"],
    params={
        "count": {"type": "int", "default": 4, "desc": "委托数量"},
    },
    postconditions=["daily_claimed"],
)
def main(ctx, g, count=4):
    if g.has_flag("daily_claimed"):              # 持久世界模型(06 文档)
        raise NormalEnd("今日已领取")              # 正常提前结束

    g.teleport_to("蒙德城")
    ctx.mount("auto_pick")                       # 边走边拾取(运行时挂的守护,非 @task.daemons)
    g.go_to(navigator_pos)
    ctx.unmount("auto_pick")

    g.talk("领取每日委托奖励")
    if not g.wait_text("委托", timeout=10):
        raise Retry(2, "未出现领取界面")            # 请求重试

    g.click(reward_btn_pos)
    g.wait_main_ui(timeout=30)
    return {"claimed": True, "count": count}      # 结构化返回,自动记 task_return
```

> 这个示例展示了:**元数据**、**守护两种挂法**(`@task.daemons` 自动 + `ctx.mount` 手动)、**异常语义**(`NormalEnd`/`Retry`)、**高层 API**(g.*)、**结构化返回**。AI 生成任务时以此为模板。

## 11. 开放问题

1. **`requires` 强制度**:起步仅文档/规划提示;后续是否在执行前强制校验能力已加载(缺则拒绝)。
2. **`preconditions`/`postconditions` 语言**:用字符串 DSL(`"at:mondstadt"`)还是可执行谓词?起步用 DSL + 规划器解读。
3. **`ctx.run` 重试策略可配**:默认 3 次,是否允许子任务 `@task(retry=5)` 覆盖。
4. **提升机制自动化**:即时任务满足什么条件(复用 N 次/成功率>X)自动建议提升?需人类审定还是自动提交。
5. **任务版本与失效**:游戏更新致任务失效时,如何让 AI 从日志(失败率上升)感知并重写(`version` 字段 + 失效信号)。
