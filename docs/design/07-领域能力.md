# 07 · 领域能力 abilities/

> 本文档定 `src/abilities/`——被 `g.*` 和守护**内部调用**的原神领域能力:导航、战斗、检测、视觉工具、游戏状态。
> 任务作者**一般不直接用**(用 `g.*` 即可);仅在**降级**(`vision.*`)或**写新守护/领域能力**时 import `abilities`。
> 前置:`00`–`06`;对接 `IMPLEMENTATION §6/§7`。

---

## 0. 一句话

`abilities/` 是"原神领域知识"的代码化:怎么在小地图上定位、怎么沿路径走、怎么打架、怎么用 YOLO 检测物体、怎么判断当前 UI。`g.*` 是对它们的**语义封装**;`abilities` 是 `g.*` 的**实现底座**。

## 1. abilities/ 总览

|---|---|---|

## 2. 导航 `navigation.py` —— PathExecutor

导航是原神自动化的**头号难点**(IMPLEMENTATION §11 风险:小地图定位精度直接决定导航质量)。

### 2.1 小地图定位

- 玩家位置 = 在 BGI **全地图数据**(`resources/map/`,300M+)上做模板匹配,把当前小地图裁剪区定位到大地图坐标。
- 复用 BGI 的全地图数据与定位算法;Python 实现,推理下沉 onnxruntime/OpenCV(释放 GIL)。

### 2.2 路径执行 PathExecutor

```python
class PathExecutor:
    def go_to(self, pos: tuple[float,float]) -> None:
        """闭环走到大地图坐标:压方向键 + 监测小地图位置 + 纠偏。"""
    def go_along(self, path: list[dict]) -> None:
        """沿 BGI JSON 路径走(keypoint 序列)。"""
```

- **闭环纠偏**:不是死跟 waypoint,而是每步用小地图定位校验实际位置,漂移则修正(02 §3 共享帧)。
- **执行期持有 `MOVE`/`MOUSE_MOVE` 租约**(02 §2),与 `auto_pick`(`INTERACT`)共存——边走边拾取合法。

### 2.3 传送优先

- 长距离**优先传送链**而非长走:基于传送点图(七天神像/秘境/锚点)算最短"传送 + 短走"序列。
- `g.teleport_to(name)` = 查传送点 → 开地图 → 选点 → `quick_teleport` 守护确认。

### 2.4 卡住脱出(看门狗)

- `PathExecutor` 内置**进度看门狗**:位置/场景持续 N 秒无进展 → 触发脱出(跳跃/换向/重算路径/回城)。
- 脱出失败 → 抛 `StuckAt`(02 §4 失败分类)→ `on_uncertain`(01 §11,后置)/ 通知人类。

## 3. 战斗 `fighter.py` —— SimpleFighter

BGI 有完整战斗脚本引擎(JSON rotation + 角色识别 + CD + 元素反应);本项目**起步简化**为 `SimpleFighter`(IMPLEMENTATION §6.4 风险:站桩连招高难度不够)。

```python
class SimpleFighter:
    def fight(self, duration_s: float = 30) -> None:
        """站桩连招循环:普攻攒能量 → Q 可用则放 → E 可用则放 → 切人。"""
```

- **角色识别**:`avatar_side.onnx` 检测当前场上角色(1–4 号位),供切人决策。
- **CD/能量检测**:技能图标模板匹配 / OCR 数字,判断 E/Q 可用。
- **简化连招**:固定 rotation(普攻 N 次 → E → 切人 → ...),不强求元素反应优化。
- **未来**:由 AI 按用户**真实队伍**生成定制连招(`B2`,差异化能力)——`SimpleFighter` 是兜底。

## 4. 检测 `detector.py` —— GenshinDetector(YOLO)

> ⚠️ 经源码核实(2026-08):YoloSharp = **标准 Ultralytics YOLOv8/YOLO11 格式**,BGI **无自定义解码**(全委托 YoloSharp NuGet;`Predictor.cs` 是 `[Obsolete]` 空壳,真实逻辑在 `BgiYoloPredictor.cs`)。真正的坑(均与"网上 Python YOLOv8 示例"有关):①**别再做 sigmoid**(box 的 DFL 与 cls 的 sigmoid 已 bake 进 ONNX 图) ②布局 `[1, 4+nc, N]` 需转置 ③letterbox(min 比例 + 居中 padding),框按 `(x-pad)/scale` 反变换(conf 0.3 / IoU 0.45,NMS 按类纯 IoU)。类名从 ONNX 元数据 `names` 读(旧 `label.json` 已废弃)。实现见 `src/abilities/detector.py`(已验证几何解码)。

```python
class GenshinDetector:
    def __init__(self, model_path: str, label_path: str): ...   # res.model/res.label 解析
    def detect(self, frame: IImageBuffer) -> dict[str, list[Detection]]:
        """推理 + YoloSharp 解码 + NMS → {类别: [Detection(x,y,w,h,score)]}。"""
```

- **模型**:`bgi_world.onnx`(交互物/鱼/树/矿)、`avatar_side.onnx`(角色)等,放 `resources/models/`,经 `res.model()` 加载(03 §5)。
- **标签**:`label.json` 类别映射,`res.model("label.json")`。
- **推理**:onnxruntime Python(释放 GIL,02 §3);**解码**按 YoloSharp 格式(输出张量布局/NMS 阈值与标准 v8 不同)。
- 被共享的 `FrameDaemon`(02 §3)调用,结果广播给所有订阅守护/`g.detect_objects`。

## 5. 视觉工具 `vision_utils.py`

封装 avc(`ITemplateMatcher`/`ITextRecognizer`/`Image`),提供任务友好的高层查询(IMPLEMENTATION §5.4/§5.5):

```python
def find_template(path: str, threshold=0.8, roi=None) -> Rect | None
def find_all_templates(paths: list[str], threshold=0.8) -> dict[str, list[Rect]]
def find_text(kw: str, roi=None) -> Rect | None
def ocr_region(x, y, w, h) -> list[str]
def crop(frame, x, y, w, h) -> IImageBuffer
```

- `g.find_template`/`g.find_text`/`vision.*`(05 §2.4/§4)是对它的再封装。
- 默认 `ccoeffNormed` + 绿幕透明 + NMS(IMPLEMENTATION §5.4)。

## 6. 游戏状态 `game_state.py`

提供 UI/场景**特征检测原语**,供 `SceneEstimator`(02 §1)组合判场景:

```python
def has_minimap(frame) -> bool          # 小地图在 → 多半在主界面/大世界
def has_hp_bar(frame) -> bool           # 血条/技能 UI → 战斗中
def has_dialog_box(frame) -> bool       # 对话框 → 对话中
def is_loading_screen(frame) -> bool    # 加载特征 → 加载中
def detect_ui_element(name: str) -> Rect | None   # 通用 UI 元素定位
```

- 这些是**特征函数**,`SceneEstimator` 用它们的组合 + 置信度判 `current_scene`(02 §1)。
- 模板图放 `resources/templates/ui/common/`(03 §5.3)。

## 7. 与 BetterGI 对照 / 复用

| 能力 | BetterGI | avc_genshin | 复用 |
|---|---|---|---|
| 小地图定位 | 全地图模板匹配(C#) | 同算法(Python) | **全地图数据**(`resources/map/`) |
| 路径执行 | AutoPathing(JSON+执行器) | `PathExecutor` + 闭环纠偏 | **路径 JSON**(`resources/paths/`) |
| 战斗 | 完整脚本引擎(角色+CD+反应) | `SimpleFighter`(简化连招) | **角色/技能 ONNX** |
| YOLO 检测 | YoloSharp + OnnxRuntime | `GenshinDetector`(同解码) | **ONNX 模型 + label.json** |
| OCR | PaddleOCR ONNX | avc `ITextRecognizer` | avc 内置(PP-OCRv6) |
| 场景判定 | `BgiVision` 状态机 | `SceneEstimator` + `game_state` 特征 | 思想借鉴,数据自建 |

> **核心复用**:**模型文件 + 路径/地图数据 + 模板图**(经 `res.*` 定位器 + `BGI_ROOT` 免复制,03 §5),**不重新训练**。算法用 Python 重写(更灵活、AI 可改)。

## 8. 开放问题

1. **小地图定位精度**:全地图匹配的耗时/精度权衡;是否需要多级(粗定位 + 精修)。这是导航可靠性瓶颈。
2. **战斗简化够不够**:`SimpleFighter` 在深境螺旋等高难度场景不足;何时升级为 AI 生成队伍定制连招(`B2`)。
3. **YOLO 解码正确性**:YoloSharp 格式易错,需对照 BGI `Predictor.cs` 逐字段验证(单元测试 + 已知样本回归)。
4. **`game_state` 特征覆盖**:新版本 UI 变化致特征失效;`UNKNOWN` 场景回流驱动补充(02 §1.5 / 06 §10)。
5. **导航与战斗的边界**:进战斗时 `PathExecutor` 应如何让出(场景门控自动 suspend,还是显式)。
